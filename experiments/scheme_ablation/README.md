# scheme 지름길 검증 (1단계 LR·트리)

PR #3 보고서는 한계 절에서 scheme(`http://`, `https://`) 표기 유무가 수집 출처를 구별하는 지름길일 수 있다고 적었다. 이 실험은 그 가능성을 직접 측정한다. Arp 외(USENIX Security 2022)의 P4 Spurious Correlations에 해당한다.

## 왜 숫자 특징만 보면 되는가

- GRU의 문자 입력(`urlcascade/adapters.py`의 `preprocess_link`)은 `http://`, `https://`, `www.`를 미리 지운다. 따라서 문자 분기는 scheme을 보지 못한다.
- scheme 정보는 18개 수치 특징으로만 들어간다.
  - `hostname_length`: scheme이 없으면 `urlparse`가 호스트를 찾지 못해 항상 0이다.
  - `abnormal_url`: scheme이 없으면 사실상 0이 된다.
  - `count-http`, `count-https`: scheme 문자열 자체를 센다.

## 방법

PR #3의 정제·분할을 그대로 쓰고 1단계 모델만 바꾼다.

| 조건 | 내용 |
|---|---|
| `original` | PR #3과 같은 특징. 재현 확인용 |
| `scheme_removed` | 모든 URL 앞의 `http(s)://`를 지운 뒤 특징을 다시 계산해 새로 학습 |
| `format_probe` | 다시 학습하지 않는다. `original` 모델에 scheme만 지운 시험 URL을 넣는다. 공격자가 링크 표기만 바꾸는 회피 상황에 해당한다 |

- 후보 격자(LR C 0.1/1/10, HGB leaf 7/15/31), 공통 검증 AP 선택, sigmoid 보정, 0.5 임계값은 `experiment.py`와 같다.
- 시험 집합은 선택에 쓰지 않는다.
- `scheme_removed`에서 scheme을 지운 시험 URL이 학습 URL과 같아지는 경우도 따로 제외해 확인했다. 무작위 분할 265행, 도메인 분할 0행이었고 결과는 거의 같았다.

## 결과 (시험 집합, %)

### 데이터의 scheme 편향 (무작위 분할 시험 107,670행)

| | 행 | 악성 비율 |
|---|---|---|
| scheme 있음 | 44,026 | 88.3% |
| scheme 없음 | 63,644 | 19.4% |

"scheme이 있으면 악성"이라는 규칙 하나만으로 정확도 83.72%, 재현율 75.86%가 나온다. 이때 오탐률(FPR)은 9.15%다.

### 다시 학습한 경우 (`original` → `scheme_removed`)

| 분할 | 모델 | AP | 재현율 | FPR |
|---|---|---|---|---|
| 무작위 | LR | 94.07 → 84.73 | 75.74 → 59.32 | 1.88 → 10.77 |
| 무작위 | 트리 | 97.44 → 94.31 | 85.52 → 80.06 | 2.90 → 8.39 |
| 도메인 | LR | 94.03 → 86.78 | 74.09 → 53.65 | 1.21 → 3.66 |
| 도메인 | 트리 | 96.71 → 93.26 | 82.50 → 74.23 | 2.71 → 5.98 |

### 표기만 바꾼 경우 (`format_probe`, 재학습 없음)

대상은 scheme이 붙은 악성 URL이다. scheme만 지우고 같은 모델에 넣었을 때 탐지 수를 비교했다.

| 분할 | 모델 | 대상 행 | 탐지(전) | 탐지(scheme 제거 후) |
|---|---|---|---|---|
| 무작위 | LR | 38,860 | 37,719 (97.1%) | 10,280 (26.5%) |
| 무작위 | 트리 | 38,860 | 38,636 (99.4%) | 23,154 (59.6%) |
| 도메인 | LR | 37,714 | 35,774 (94.9%) | 9,893 (26.2%) |
| 도메인 | 트리 | 37,714 | 37,029 (98.2%) | 21,768 (57.7%) |

## 해석과 범위

- 1단계 모델 성능의 상당 부분은 scheme 표기 차이에서 나온다. 같은 URL에서 `http://`만 빼도 LR은 악성 탐지의 약 4분의 3을, 트리는 약 40%를 잃는다.
- 캐스케이드에서 1단계는 정상으로 보이는 URL을 GRU 없이 바로 종료시킨다. 그래서 scheme을 뺀 악성 URL은 조기 종료되어 GRU가 볼 기회를 잃을 수 있다.
- **이번 실험에서 하지 않은 것:**
  - GRU를 다시 학습하거나 평가하지 않았다. GRU 가중치가 저장소에 없다.
  - GRU의 숫자 분기도 같은 특징을 받으므로 영향이 있을 수 있다. 하지만 측정하지 않았으므로 캐스케이드 전체의 회피율은 주장하지 않는다.
- 단일 seed다.

## 재현

PR #3 README의 `prepare.py` → `refine_inputs.py` → `finalize_data.py`를 먼저 실행한다. 그다음 같은 `URLCASCADE_RUN_DIR`에서 아래를 실행한다.

```powershell
& $experimentPython experiments/scheme_ablation/run.py
```

## 실행 환경과 데이터 동일성

- 실행 환경: Windows, Python 3.11.9, TensorFlow 2.12.0, scikit-learn 1.2.2, NumPy 1.23.5, pandas 1.5.3. PR #3은 Python 3.10.18이었다.
- 행 집합과 순서는 PR #3과 같다. 근거는 다음과 같다.
  - 다시 만든 `data-final`의 두 인코딩 배열, 두 어휘 파일, 정규화 격리 파일의 SHA-256이 PR #3 증거와 같다.
  - 단계별·분할별 행 수와 토큰 중복 검사 12회 기록도 같다.
- 다른 점: `.npz`는 zip 시각 정보 때문에 해시가 다르다. `features.npy`와 `clean.csv`도 다르다. Python 버전에 따른 `urllib` 해석 차이로 일부 수치 특징이 달라진 것으로 보이지만, 확정하지는 못했다.
- 그 영향은 작다. `original` 시험 AP를 비교하면 LR은 0.940709 대 PR #3 0.940710, 트리는 0.974406 대 PR #3 0.974354다.
- 결과 원본: `evidence/scheme-ablation/results.json`
