# URL 표기와 악성 URL 분류 성능

#3 보고서에서 제기한 질문은 URL 표기 형식이 달라지면 수집 출처와 관련된 단서 때문에 성능이 달라지는지였다. 이 PR은 표기와 라벨의 연관성, 특징을 바꿔 재학습한 결과, 형식을 통일하는 방어 전처리를 다룬다. 수집 출처가 성능 차이의 원인인지는 확인하지 못했다.

## 팀원이 남긴 실험 결과

Windows에서 로지스틱 회귀(LR)와 부스팅 트리(HGB)를 무작위 분할과 도메인 분할로 평가했다. Colab에서는 #3과 같은 학습 조건으로 GRU를 새로 학습하고 정책을 고정한 뒤 **무작위 분할에서만** GRU와 캐스케이드 전체를 평가했다. #3의 가중치와 Colab에서 학습한 가중치는 별개다.

| 분할 | 모델 | 원본 특징 AP | 형식 정보를 제거하고 재학습한 AP |
|---|---|---:|---:|
| 무작위 | LR | 94.07% | 84.73% |
| 무작위 | HGB | 97.44% | 94.31% |
| 도메인 | LR | 94.03% | 86.78% |
| 도메인 | HGB | 96.71% | 93.26% |

AP는 정밀도와 재현율을 여러 임계값에 걸쳐 요약한 지표다. 무작위 시험 집합에서 표기 형식에 따라 악성 비율이 88.3%와 19.4%로 달랐다. [1단계 집계](../../evidence/scheme-ablation/results.json)

### GRU 단독과 캐스케이드의 재현율

Colab 실험에서는 모델과 정책을 고정하고 같은 무작위 시험 집합 107,670행을 두 표기 조건에서 평가했다. 재현율은 이 중 악성 URL 51,223개를 악성으로 탐지한 비율이다. [GRU·캐스케이드 원본 집계](../../evidence/scheme-ablation/cascade-probe-random.json)

| 모델·정책 | 원본 표기 재현율 | URL 스킴 표기 제거 후 재현율 |
|---|---:|---:|
| GRU 단독 | 95.50% | 83.78% |
| LR → GRU (기본) | 95.15% | 82.50% |
| LR → GRU (경계) | 95.17% | 82.57% |
| HGB → GRU (기본) | 94.71% | 80.13% |
| HGB → GRU (경계) | 94.83% | 80.54% |

이 표는 Colab에서 단일 시드로 측정한 결과다. 별도 실행인 #3에서 원본 표기의 GRU 단독 재현율은 95.23%였다.

팀원은 Colab 원본 조건의 데이터를 #3 공유본과 대조해 무작위·도메인 분할 각각에서 학습, 검증 세 역할, 통합 검증, 시험의 **12개 묶음 모두 행 ID와 라벨의 순서가 일치했다**고 기록했다. 두 인코딩 배열의 해시도 일치했다. 다만 `clean.csv`와 `features.npy`의 해시는 달랐고 원인은 확인되지 않았다. [Colab 실행자의 대조 기록](https://github.com/andrew427dev/malicious-url-cascade/releases/tag/colab-artifacts-2026-11-18) · [팀 Drive 보관본](https://drive.google.com/file/d/17C6a932BkiLI4PEVmW-AHOCg4EjciDy6/view?usp=drivesdk)

Windows에서 수행한 1단계 실험은 당시 행 ID와 라벨의 순서를 대조한 기록이 없다. #3과 해시가 같은 파일은 두 인코딩 배열, 두 어휘 파일, 정규화 격리 파일이었다. CSV, 수치 특징, 두 분할 인덱스의 해시는 달랐고 원인은 확인되지 않았다.

## 팀 공유본 확인

팀 자료 폴더에서 #3 ZIP을 풀고 `URLCASCADE_RUN_DIR`에 `data-final`, `random`, `domain` 폴더를 담은 상위 경로를 지정한다. 아래 명령은 #3 실험용 Python 환경에서 저장소 루트를 기준으로 실행한다.

```powershell
$env:URLCASCADE_RUN_DIR = 'C:\team\clean-rerun'
python experiments/scheme_ablation/verify_inputs.py --shared-models
```

재학습 없이 데이터 9개 파일의 무결성을 확인하고, 두 분할에서 학습·검증용 세 역할·통합 검증·시험의 행 순서를 대조한다. 비교 기준은 #3 원본에서 생성한 [분할별 SHA-256](../../evidence/scheme-ablation/pr3-ordered-cohorts.json)이다. 실제 인덱스로 읽은 각 행을 ASCII `ID<TAB>라벨<LF>`로 이어 붙여 계산한다. 모델 검사는 공개된 #3 완료 기록, 학습 파일 목록, 설정에 기록된 데이터 해시, 시험 전에 고정한 정책과 모델 해시를 연결해 확인한다.

## 방어 실험 실행

- `python experiments/scheme_ablation/run.py`는 원본 특징과 형식 정보를 제거한 특징으로 각각 1단계 모델을 학습하고 두 분할에서 시험한다. 결과는 실행 폴더의 새 `scheme-ablation/results.json`에 기록한다.
- `python experiments/scheme_ablation/canonical.py C:\team\canonical-run`은 입력 형식을 통일한 새 `data-final`을 만든다. 변환 후 입력이 같아진 그룹이 분할 경계나 라벨을 넘으면 그룹 전체를 제외하고 남은 행의 인덱스를 다시 만든다. 같은 분할·라벨 안의 중복은 유지한다. 어휘는 #3의 학습 어휘를 사용한다.
- 새 데이터의 `manifest.json`에서 전체·분할별 정상/악성 수, 분할 비율, 도메인 수와 파일 해시를 확인할 수 있다. 정규화 단계의 산출물은 여기까지다. 첫 번째 표의 AP는 `run.py`의 1단계 재학습 결과다.

정규화한 특징은 `features.npy`에 저장하고, `clean.csv`의 `url_key`에는 행 추적을 위해 원래 주소를 유지한다. #3의 `experiment.py`는 속도 측정 시 원래 주소에서 특징을 다시 계산한다. 따라서 이 폴더로 #3의 전체 평가를 그대로 실행하면 예측 대조에서 중단될 수 있다. 정규화 모델의 종단 간 예측·속도를 측정하려면 시간 측정에도 동일한 정규화 전처리를 적용해야 한다.

### #3 공유본으로 다시 확인한 값

공유본 717,793행은 기준 파일 9개 및 분할별 ID·라벨 해시와 일치했다. 이 공유본으로 1단계를 새로 학습한 결과 원본 특징 → 형식 정보 제거 후 AP는 무작위 LR 94.07% → 84.73%, HGB 97.44% → 94.29%, 도메인 LR 94.03% → 86.78%, HGB 96.72% → 93.26%였다.

방어 전처리는 충돌한 1,319행(악성 1,023행)을 제외했다. 남은 716,474행은 정상 376,013행, 악성 340,461행이다. 이 수치는 정규화 후의 데이터 규모이며, 정규화된 데이터로 학습한 GRU의 성능은 이번 검증에서 측정하지 않았다.

## 정규화 데이터로 학습한 GRU·캐스케이드 (Colab, 무작위 분할)

위 검증에서 측정하지 않은 값을 Colab에서 따로 측정했다. `canonical.py`로 만든 716,474행 폴더를 `URLCASCADE_RUN_DIR`로 지정하고 #3의 `experiment.py random`을 그대로 실행했다. 학습 조건과 정책 선택 규칙은 #3과 같다. 시험 집합은 107,325행이다.

| 항목 (%) | 원본 특징 (Colab 재학습) | 정규화 후 재학습 |
|---|---:|---:|
| 시험 행 수 | 107,670 | 107,325 |
| GRU 단독 재현율 / 오탐률 | 95.50 / 1.58 | 95.03 / 1.92 |
| LR 경계 정책 재현율 / 오탐률 | 95.17 / 1.54 | 94.40 / 1.88 |
| HGB 경계 정책 재현율 / 오탐률 | 94.83 / 1.36 | 94.47 / 1.82 |
| LR 경계 정책: 조기 종료 손실 / GRU 호출률 | 0.34%p / 94.19 | 0.63%p / 94.20 |
| HGB 경계 정책: 조기 종료 손실 / GRU 호출률 | 0.68%p / 73.56 | 0.56%p / 80.99 |
| 1단계 단독 재현율 (LR / HGB) | 75.74 / 85.52 | 59.23 / 81.54 |

- 정규화 후에는 `http(s)://`를 붙이든 빼든 모델 입력이 같다. 그 조건에서 GRU 재현율은 0.47%p, 캐스케이드 재현율은 0.36~0.77%p 낮아졌고 오탐률은 0.34~0.46%p 올랐다.
- HGB 캐스케이드의 GRU 호출률은 73.56%에서 80.99%로 올랐다. 1단계가 약해진 만큼 조기 종료로 줄이는 계산량이 줄어든다.
- GRU 최적 epoch는 10이고 τ는 원본과 같다(LR 0.1, HGB 0.05).
- 한계: 단일 시드, 무작위 분할만 측정했다. 두 열은 시험 행이 345행 다르다. 속도는 측정하지 못했다. 위에서 설명한 대로 `experiment.py`가 시간 측정 단계의 예측 대조에서 중단됐고, 표의 값은 그 전에 저장된 `results.json`에서 가져왔다. 가중치와 행 단위 예측은 저장소에 없다.
