### 6.9 URL 표기 지름길과 정규화 대응

원자료의 URL은 `http://`나 `https://`로 시작하는 것과 그렇지 않은 것이 섞여 있고, 이 표기는 라벨과 강하게 연관된다. 주 시험 집합 107,670행에서 scheme이 있는 44,026행은 88.3%가 악성이고, 없는 63,644행은 19.4%가 악성이다. "scheme이 있으면 악성"이라는 규칙 하나만으로 정확도 83.72%, 악성 재현율 75.86%, 오탐률 9.15%가 나온다. 이는 Arp 등이 정리한 허위 상관(P4)에 해당한다 [R5]. 표기 차이가 수집 출처에서 왔는지는 확인하지 못했다.

GRU의 문자 입력은 전처리에서 scheme과 `www.`를 제거하므로 이 단서를 직접 보지 않는다. 단서는 18개 수치 특징을 통해 들어간다. 원저자의 특징 계산은 scheme이 없으면 호스트를 찾지 못해 호스트 길이가 0이 되는 식으로 값이 달라진다.

**공격 조건.** 모델과 정책을 고정하고, 같은 시험 집합의 모든 URL에서 scheme만 떼어 수치 특징을 다시 계산했다. 사용자가 주소창에 `example.com/path`만 입력해도 같은 사이트에 도달하므로, 공격자가 비용 없이 쓸 수 있는 변형이다.

표 15 scheme 제거 전후의 악성 재현율 (무작위 분할 시험 107,670행, 악성 51,223행)

| 구성 | 원본 표기 재현율 % | scheme 제거 후 재현율 % | 감소 %p |
| --- | ---: | ---: | ---: |
| GRU 단독 | 95.50 | 83.78 | 11.73 |
| LR 기본 | 95.15 | 82.50 | 12.66 |
| LR 경계 | 95.17 | 82.57 | 12.59 |
| 트리 기본 | 94.71 | 80.13 | 14.59 |
| 트리 경계 | 94.83 | 80.54 | 14.29 |

오탐률은 모든 구성에서 0.05%p 이내로만 변했다. 손실은 원래 scheme이 있던 악성 38,860행에 집중된다. GRU 단독은 이 중 38,825행을 탐지하다가 32,819행만 탐지했다. 캐스케이드는 GRU보다 더 약해진다. 1단계가 수치 특징만 보기 때문에, 트리 기본 정책에서 이 악성 행의 조기 종료가 25건에서 2,394건으로 늘었다. 즉 조기 종료로 비용을 줄이는 설계는 1단계가 의존하는 단서가 깨질 때 GRU 단독보다 더 큰 미탐을 낸다.

**대응.** 모든 URL을 `http://` 뒤에 scheme을 뗀 나머지를 붙인 형태로 통일한 뒤 수치 특징을 계산하고, 1단계와 GRU를 같은 조건으로 다시 학습했다. 이 구성에서는 scheme 유무가 달라도 모델 입력이 같으므로 위 변형이 예측을 바꾸지 못한다. 통일 후 입력이 같아진 행 가운데 분할 경계나 라벨을 넘는 1,319행(악성 1,023행)은 제외했고 716,474행이 남았다.

표 16 원본 조건과 정규화 후 재학습의 시험 결과 (무작위 분할, 단일 시드)

| 항목 % | 원본 특징 | 정규화 후 재학습 |
| --- | ---: | ---: |
| 시험 행 수 | 107,670 | 107,325 |
| GRU 단독 재현율 / 오탐률 | 95.50 / 1.58 | 95.03 / 1.92 |
| LR 경계 재현율 / 오탐률 | 95.17 / 1.54 | 94.40 / 1.88 |
| 트리 경계 재현율 / 오탐률 | 94.83 / 1.36 | 94.47 / 1.82 |
| LR 경계: GRU 대비 감소 / 2단계 호출률 | 0.34%p / 94.19 | 0.63%p / 94.20 |
| 트리 경계: GRU 대비 감소 / 2단계 호출률 | 0.68%p / 73.56 | 0.56%p / 80.99 |
| 1단계 단독 재현율 (LR / 트리) | 75.74 / 85.52 | 59.23 / 81.54 |

정규화 후 GRU 재현율은 0.47%p, 캐스케이드 재현율은 0.36~0.77%p 낮아졌고 오탐률은 0.34~0.46%p 올랐다. scheme 제거 공격에서 잃던 11.7~14.6%p와 비교하면 작은 비용이다. 두 경계 정책 모두 GRU 대비 재현율 감소 1%p 이내 조건을 유지했다.

비용은 1단계에서 나타난다. LR 단독 재현율이 75.74%에서 59.23%로 떨어졌고, 트리 캐스케이드의 2단계 호출률은 73.56%에서 80.99%로 올랐다. 원본 조건에서 조기 종료가 줄여 주던 계산량의 일부는 표기 단서에 기대고 있었다.

**해석의 범위.** 6.9절의 값은 Colab에서 #3과 같은 학습 조건으로 새로 학습한 모델에서 측정했다. 같은 조건의 GRU 단독 재현율이 6.1절은 95.229%, 여기서는 95.50%인 이유다. 무작위 분할과 단일 시드만 측정했고, 두 열의 시험 집합은 345행 다르다. 정규화 조건의 처리 시간은 측정하지 못했다. 평가 스크립트의 시간 측정이 원래 주소에서 특징을 다시 계산해 정규화 입력과 맞지 않기 때문이다. 따라서 표 12의 시간 절감이 정규화 후에도 유지되는지는 이 보고서로 답할 수 없다.

## 초록에 더할 문단

URL의 scheme 표기 유무가 라벨과 강하게 연관되어 있어, 고정된 모델에서 scheme만 제거하면 GRU 단독 재현율이 95.50%에서 83.78%로, 트리 캐스케이드는 94.83%에서 80.54%로 떨어졌다. 표기를 통일한 뒤 다시 학습하면 이 변형은 입력을 바꾸지 못하고, GRU 재현율은 95.03%였다.

## 결론에 더할 문단

조기 종료 캐스케이드는 1단계가 의존하는 단서가 깨질 때 GRU 단독보다 더 크게 실패했다. 표기 정규화는 재현율 0.4~0.8%p의 비용으로 이 실패를 없앴지만 2단계 호출률을 올렸다. 탐지 성능과 계산 절감을 함께 주장하려면 입력 표기를 통제한 조건에서 두 값을 다시 측정해야 한다.
